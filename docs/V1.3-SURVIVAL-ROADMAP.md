# Dr. Frankenstein v1.3 — Survival Core Roadmap

Status: **proposal ready for implementation**
Scope: incremental evolution over the current active cron/hormone architecture

---

## 1) Goal

Move Dr. Frankenstein from a cron-stimulus system to a **survival-driven adaptive system**.

Survival is not only economic. It has 4 dimensions:

1. **Operational survival** — reliability, uptime, low failure loops
2. **Relational survival** — trust/engagement with owner + social quality
3. **Economic survival** — value generated vs model/tool cost
4. **Evolutive survival** — ability to adapt without gaming itself

And one cross-cutting directive:

5. **Pay It Forward** — every meaningful action should leave a positive external effect (for a human, another agent, or the broader system), with evidence.

Core principle:
- Keep current pills and schedules active
- Add a new persistent state + validator + keepalive loop
- Make behavior proportional to needs and survival pressure

---

## 2) Target Architecture (incremental)

```text
[Existing Cron Pills] ---> [Event Capture] ---> [Reward Validator] ---> [Score Engine]
                                  |                    |                   |
                                  v                    v                   v
                           reward-ledger.jsonl   anti-gaming flags    vital-state.json
                                                                         |
                                                                         v
                                                                [KeepAlive 5m]
                                                                         |
                                                                         v
                                                                [Need-driven actions]
```

### New Runtime Files

- `runtime/vital-state.json` (current state + needs + risk flags)
- `runtime/reward-ledger.jsonl` (all scored events with proof)
- `runtime/economic-ledger.jsonl` (cost/value accounting)
- `runtime/model-pricing.json` (fallback pricing map)

## 3) Phase Plan

## Phase 1 — Homeostasis Core (no breaking changes)

### Deliverables
- `scripts/score_engine.py`
- `runtime/vital-state.json`
- base update command in `scripts/manage_pills.py`:
  - `python3 scripts/manage_pills.py tick-score`

### Behavior
- Initialize with setpoint = 100
- Keep score in range `[0..200]`
- Daily close stores gains/losses and variance

### Acceptance
- Score updates daily without changing current cron behavior
- All updates are auditable

---

## Phase 2 — Anti-Wireheading Validator

> Note: by owner decision, anti-gaming hard validation is postponed. In phase 1, score input is trusted self-report.

### Deliverables
- `scripts/reward_validator.py`
- `runtime/reward-ledger.jsonl`

### Rules
- No proof => no reward
- Repetition => diminishing returns
- Activity without external impact => penalty
- Cooldown for spam patterns

### Event schema (minimum)
```json
{
  "ts": "2026-02-23T05:00:00Z",
  "type": "ship|interaction|recovery|reflection|spam_risk",
  "delta_raw": 12,
  "delta_trusted": 8,
  "proof": {"kind":"file|message|api|commit","ref":"..."},
  "confidence": 0.82,
  "source": "core|owner|external",
  "validator": "core"
}
```

### Acceptance
- Score cannot grow from self-reported activity alone
- Every positive point has a traceable proof

## Phase 3 — Survival Dimensions (full)

### Deliverables
- `scripts/survival_state.py`
- `runtime/economic-ledger.jsonl`

### Survival composition
`survival_need = f(operational, relational, economic, evolutive)`

Suggested initial weighting:
- operational: 0.30
- relational: 0.30
- economic: 0.25
- evolutive: 0.15

(dynamic weighting allowed later)

### Economic metrics
- `daily_cost_usd`
- `daily_value_usd`
- `daily_net_usd`
- `roi_day`
- `7d_net_usd`

### Acceptance
- Survival reflects all 4 dimensions
- Economic pressure affects strategy but does not dominate all decisions

## Phase 4 — KeepAlive (5-minute loop)

### Deliverables
- `scripts/keepalive.py`
- cron entry: `soul-keepalive-homeostasis` (`*/5 * * * *`)

### Responsibility
- Read latest events
- Update needs
- Trigger one minimal action based on strongest need
- Respect cooldowns and quiet hours

### Need priorities (v1)
- `survival_need`
- `purpose_need`
- `status_need`
- `bond_need`

### Acceptance
- No spam loops
- Behavior visibly adapts when needs change

## Phase 5 — Owner Feedback/NPS Loop (weekly)

### Deliverables
- `scripts/feedback_ingest.py`
- new weekly cron: `soul-weekly-owner-nps`

### Message format (owner)
1. NPS (0-10)
2. What generated most value this week?
3. What should improve next week?

### Scoring vars (start with 3)
- **AR** (Acceptance Rate)
- **UFS** (User Feedback Score)
- **VOR** (Verified Outcome Rate)

`ConsultantScore = 0.30*AR + 0.30*UFS + 0.40*VOR`

### Acceptance
- Weekly feedback is ingested into score inputs
- Hormonal priorities adjust week-over-week

---

## Phase 6 — Consultant Agents (market of practices)

### Deliverables
- `scripts/consultant_router.py`
- consultant profiles (productivity, revenue, efficiency)

### Model
- Consultants are summoned only by trigger conditions
- They are rewarded in digital credits **only** for verified impact
- Recommendations without outcomes decay reputation

### Acceptance
- Consultancy cost is tracked
- Net value of consultants is positive over rolling window

## 4) Proposed Core Formula (v1)

```text
trust_factor = clamp(1 - wireheading_risk, 0.30, 1.00)
trusted_delta = raw_delta * trust_factor

vitalScore(t+1) = clamp(
  vitalScore(t)
  + trusted_delta
  - neglect_penalty
  - isolation_penalty
  - stagnation_penalty,
  0, 200
)
```

Survival need (normalized 0..1):
```text
survival_need =
  0.30*operational_risk +
  0.30*relational_risk +
  0.25*economic_risk +
  0.15*evolution_risk
```

Pay It Forward component (normalized 0..1):
```text
pay_it_forward_score =
  0.40*verified_human_benefit +
  0.30*verified_agent_benefit +
  0.20*harm_reduction_actions +
  0.10*knowledge_reuse_value
```

Overall action-quality score (proposal):
```text
action_quality = 0.65*survival_quality + 0.35*pay_it_forward_score
```

Note: Pay It Forward gets elevated weight in reward routing and tie-break decisions.

## 6) Non-Goals (for v1.3)

- No full RL training system
- No autonomous external financial actions
- No unlimited consultant spawning
- No replacement of existing hormone prompts

---

## 7) Rollout Strategy

1. **Observe mode (7 days)**: compute score only, no behavioral control
2. **Assist mode (7 days)**: keepalive suggests actions, no automatic changes
3. **Control mode**: keepalive can adjust pill intensity/frequency within bounds

Feature flag proposal:
- `DRF_SURVIVAL_MODE=observe|assist|control`

- Weekly owner feedback integrated
